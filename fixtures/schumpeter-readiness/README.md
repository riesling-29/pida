# Pida producer readiness fixtures

These fixtures exercise a **Pida-native draft**, not a confirmed Schumpeter ObservationEnvelope v0.1 contract. `index.json` records `schumpeter_contract_confirmed: false` and each fixture's expected validator result. Positive captures execute actual Pi, workbench and journal code with scripted faux model responses. Negative cases intentionally mutate those captures. They contain only synthetic test data.

| Fixture | Expected purpose |
| --- | --- |
| scoped-verification | Passed host assertions bound to the final artifact snapshot; overall UNKNOWN |
| stale-verification | Passed assertions followed by a file change; current_at_run_end false |
| claim-without-evidence | Completed runtime response with no independent verification |
| cancelled / timeout | Distinct interruption outcomes, no successful completion claim |
| output-retry | Bounded output-limit continuation within one run |
| duplicate-delivery | Exact repeated source/event ID accepted and listed as duplicate |
| sequence-gap | Missing event rejected; incomplete export explicit |
| tampered-digest | Changed payload rejected |
| unsupported-verified-claim | Unsupported task-level VERIFIED rejected |
| forbidden-payload-field | Raw-prompt field rejected by the metadata schema |

`scoped-verification.jsonl` is the event-only form of the same bundle; it does not contain its manifest or a self-contained completeness claim. Prefer JSON bundle for offline transfer. Restore/process-crash and browser evidence are exercised by the regression/browser scripts, separately from these fixtures.

## Candidate field alignment

| Requested field | Native draft behavior / receiver responsibility |
| --- | --- |
| schema_version | Pida namespace and explicit draft version until contract agreement |
| source_id / source_event_id | Persistent source UUID and generated capture UUID; duplicate key is their pair |
| agent_id / session_id / task_id / run_id | Actual runtime identity; task may be supplied by the trusted caller; no mission/attempt inference |
| activity / occurred_at | Captured runtime event and capture time; interrupted detection is not the unknown crash time |
| received_at | Omitted by the producer; the receiving Hub records its own ingestion time |
| sequence_number | Per run/operation, starts at 1 |
| capture_mode | native-runtime; model in these fixtures is nevertheless scripted |
| payload_digest | SHA-256 of canonical payload JSON, not a signature |
| object_refs | Session/run IDs; external object mappings require the receiving contract |
| artifact_refs / evidence_refs | Stable version hashes / verification IDs resolved in the manifest |
| data_scope | metadata-only; no raw prompt or tool input/output |

The supplied Schumpeter architecture/audit documents do not fix this envelope. Their illustrative mission/attempt manifest cannot be silently equated with task/run. No Schumpeter repository was changed, and no Hub acceptance is asserted.

## Reproduce and inspect

```sh
npm run build
node scripts/integration-fixtures.mjs
node --test test/integration-contract.test.mjs
```

Generation creates new real capture IDs/timestamps, so regenerated bytes differ. Repeated export of one captured run preserves IDs. `observation.schema.json`, `manifest.schema.json` and `bundle.schema.json` describe shape; `validateObservationBundle` additionally checks sequence, duplicate conflicts, identities, payload digests, reference resolution, artifact IDs, verification snapshot digests and stale current-state claims. Fixture expectations are stored in the index; tests also independently reject fabricated verification freshness and broken artifact references.

This is integrity/contract validation of producer data, not independent verification of file contents at the receiver. The receiver must obtain authorized artifacts and verify content hashes before making stronger claims. The digest has no secret/signature: a party able to rewrite the entire bundle can recompute it. Authenticate transport and apply receiver authorization separately.
