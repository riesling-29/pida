# Delegation boundary fixture correction

The admission regression exposed a pre-existing depth-chain test failure, independently reproduced on frozen `bbb8e56` and `30077f3`: expected native `AGENT_DELEGATION_LIMIT` failure became `RUN_TIMEOUT`. [Original baseline](pida-admission-delegation-baseline.txt) and [unchanged-current reproduction](pida-admission-delegation-current.txt) remain unchanged.

A read-only instrumented copy printed only terminal status/code, output length, trace type/code and the three jobs' status/lengths. [Probe output](pida-delegation-fixture-probe.txt) shows the depth-two trace had already emitted `tool_failed:AGENT_DELEGATION_LIMIT`; all three runs then hit their existing five-second bound after streaming only about 5,800 of the configured 8,000 synthetic characters. The installed Pi faux provider `dist/providers/faux.js` schedules a timer per text chunk; its configured high token rate does not remove that timer overhead for tiny chunks.

This one fixture now explicitly uses `tokenSize:{min:128,max:128}`. The full 8,000-character credential-like synthetic output, delegation chain, five-second runtime bound, expected terminal error, absence of a fourth job and all truncation/redaction assertions are unchanged. Runtime/provider/application code is unchanged. The test checks depth/result boundaries, not timer-paced tiny-chunk throughput. The do-nothing alternative would leave those assertions unexecuted after an unrelated fixture timeout.

`node --test --test-timeout=30000 test/agent-tools.test.mjs` now passes all three tests: [output](pida-delegation-fixture-fix-output.txt). This correction is separate from frozen production admission `30077f3`; it does not alter that original review evidence or claim a green full product suite. Withdraw it if the same complete output and depth/redaction assertions cease to be exercised, or if a production timeout is relaxed to make it pass. Recheck when faux streaming semantics or fixture purpose changes.
