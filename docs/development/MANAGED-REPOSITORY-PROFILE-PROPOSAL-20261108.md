## Closed trusted configuration

New private parent environment `PIDA_REPOSITORY_PROFILE=<absolute JSON path>` selects a new host only. The parent first uses native selection/inspection UI, records explicit root selection and distinct fixed-runner approval, and verifies the selected runtime inventory. Model/renderer input cannot supply the path or any raw runtime configuration. Source-file edits remain the authorized mutable subject; root/profile/runner bindings are immutable.

JSON maximum65536 bytes, exactly these seven top-level keys:

- schema_version: pida.repository-profile/1.
- id: repository-fixed-node/1.
- host_id: exact registered host token.
- runtime: exactly {source_commit,manifest_sha256};40/64 lowercase hex, matching the parent's verified runtime binding. This is a parent attestation plus a stored producer identity, not a new signature or trust root.
- root: exactly {selection_id,path,device,inode}; selection_id is a UUID, path is native absolute canonical realpath, no symlink/junction aliases; device/inode are decimal strings from the selected directory identity. Compare the same directory identity at fresh initialization and resume, never hash all mutable repository contents. The selected directory must be separate from/contain no overlap with managed runtime, provider/config/store/credential/protected app paths. Parent supplies the corresponding protected app locations; do not infer that OS privileges enforce this boundary for the runner.
- program: exactly {id,manifest_path,approval,approval_id,approval_receipt_sha256}; id uses existing `[a-z][a-z0-9_]{0,39}`, manifest_path is an absolute private app-owned regular file outside the project, approval has exactly {manifestDigest,commandDigest,entrypointDigest}, each64 lowercase hex. approval_id is a UUID; approval_receipt_sha256 is the parent's durable explicit approval receipt digest, which producer checks for identity/consistency but cannot independently prove was a human click.
- digest: SHA256 of private-state.canonical of the preceding six keys, excluding digest itself.

IDs and bounded text must be strings, not regex-coercible arrays; paths maximum4096 characters without NUL/CR/LF. Unknown/missing/future fields, wrong host/runtime/root identity, nonregular/link manifest, missing approval or altered digests fail before workspace initialization/stale-lock recovery. Resume recomputes exact profile/manifest/program identities before creating runtime tools. Root/runner changes require a new host workspace in version1; no silent migration of D or0f1 workspaces.

The fixed program uses an ordinary existing ProgramManifest/1, validated by inspectProgramProxy. First profile restricts command to `$node` (the bundled approved Node), inputMode:none, inputSchema exactly {type:object,properties:{},additionalProperties:false}, outputMode:text, effect:write, an explicit timeoutMs100..30000, and args exactly [entrypoint]. entrypoint is any approved nonempty root-relative regular script path, no absolute/traversal/link/hardlink; it is not a product hardcoded scripts/check-summary.mjs path. Its exact manifest bytes, Node bytes and entrypoint bytes must equal the approval returned by inspectProgramProxy. No runnerDigest is present for this $node profile; no $npm/PATH lookup/shell indirection is offered. The whole ProgramManifest including human-readable name/description and timeout is pinned. Child processes use the existing explicit safe environment allowlist (PATH, OS/home/temp/locale locations), not process.env wholesale; provider/policy tokens are not forwarded as environment variables. No model selects environment additions or loader variables. This does not stop approved host code from reading files accessible to the OS user, using imported code or opening network connections; cwd is not containment. Stdout/stderr use the existing bounded/session-owned output store. Cancellation of the spawned child is not a guarantee that every descendant or prior side effect was undone. A changed script must be re-inspected and explicitly approved into a new profile; changing imported task source is allowed but its effects are not pinned by entrypoint approval.

The parent approval receipt binds runtime source/inventory, root selection/directory identity and program manifest/command/entrypoint digests, excluding the eventual profile digest to avoid circular hashing. This is more general than one fixture yet deliberately narrower than arbitrary npm or language-toolchain execution. An additional program family requires a separately versioned contract.

## Cancellation, recovery and truthful artifacts

ProgramProxy rechecks approved manifest/command/entrypoint before every invocation. Missing permission or changed approval yields not_applied before launch. A nonzero exit is failed, even when a write-classified process may already have changed files. After launch, timeout/cancellation/start uncertainty retains effectState unknown; never convert it to success, retry automatically, or claim complete rollback/descendant containment. Preserve request/run/tool/effect IDs and original deadline. Reconnect reads retained state; it does not replay an uncertain effect. Current immutable runner approvals have no live revocation callback: parent revocation disables new admissions, cancels/stops the host and refuses resume until a new authorized configuration. Do not claim instant in-process revocation beyond delivered cancellation.

ProjectView.read is a bounded live read {path,content,bytes,revision,truncated:false}, max262144 bytes, UTF-8 only. The digest covers exact read bytes. A displayed-diff changes revision is not a repository snapshot. A new Sch `project-file-snapshot/1` publication records selected host/profile/root-selection identity, canonical relative path, exact bytes/digest/size, capture time/scope and separately observed native task IDs. It means selected project file at capture time, not proof that a named job authored it. Keep HOST_PROJECT_ARTIFACTS_NOT_CAPTURED and do not fabricate ResultManifest.artifact_refs or reuse the result.text capture type.

The operator chooses an expected displayed file revision; capture rereads once and rejects a mismatch instead of silently replacing bytes. Multiple selected files are individually captured, not an atomic repository cut. Sch persists exact BLOBs and request/provenance identity before publication, rechecks current membership/contract revision/selected-root authority, and makes response-loss/restart retry return the same publication. A later organization consumes the stored accepted submission bytes/hash as bounded reference text in a fresh goal, not the changed live file. No automatic next-goal/acceptance is added.

## Root-selected first contract and deferred verification recovery

Root explicitly chose immutable host approval with Stop/disable/reprovision. Existing per-call manifest/executable/entrypoint hash checks remain; live parent consent revision enforcement is not claimed or added. Parent disables new admissions before stopping/cancelling the host, preserves all in-flight/unknown effect evidence, and requires a separately authorized new profile to change root or program. Delivery of a cancellation is not proof that running code, descendants or prior side effects were reversed. Current room/provider/membership/contract authority is still rechecked at artifact publication; immutable runner approval does not grant publication authority.

Root also accepted only the explicit bounded baseline-failure followed by a distinct deliberate repair-goal fixture. It is not same-run fail/fix/pass and must retain the original failing run. No PROGRAM_EXIT_FAILED classification, usage, cancellation, deadline or unknown-effect guard changes in this profile.

A later minimal verification-recovery option could make an explicitly host-approved verification program return a stable trusted recoveryKey for the same test scope and pinned approval, allowing a later successful real process exit in that scope to clear only its earlier verification failure. It would require a separate reviewed semantic contract: preserve every failed tool event, bind approval/root/test scope, require real known settled results, reject altered checker/foreign scope/model-supplied keys, and never clear provider, quota, cancellation, timeout, persistence, unknown-effect or unrelated mutation failures. Current ProgramProxy emits no such key. Ordinary coding convenience alone is not grounds to add one here; no implementation or product promise is made for that deferred option.

Other deferred scope is unchanged: dynamic tools/commands/npm/install, arbitrary argv/env, live consent callbacks, per-org roots or isolation, cross-process OS locking, repository-wide rollback/atomic capture, native project authorship attestation, automatic publication/next-goal execution, and sandbox guarantees. The small fixture is a proof of plumbing and retained identities, not general model coding competence.
