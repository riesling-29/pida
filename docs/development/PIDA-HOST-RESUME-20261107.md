# Explicit host resume unit

This separately scoped unit adds `--workspace-mode resume` to the reviewed fresh host. The default remains `fresh`. Pida owns validated manifest/launcher exclusivity, current policy injection, runtime reopen and rotated API transport credentials. Schumpeter's adapter owner agreed to preserve registered host/principal/native mappings, privately retain the same host-policy credential, accept the exact `workspace_mode` ready field, and avoid native organization recreation. A policy service port may change; authority remains the same registered credential and current mapping.

The implementation and failure semantics are documented in [SCHUMPETER-HOST-1.md](../SCHUMPETER-HOST-1.md#explicit-same-host-resume). No second runtime was introduced. An initial real SIGKILL probe exposed Pida's intentionally retained stale runtime locks; explicit validated resume now invokes the existing dead-owner-only `unlockWorkspaceState` helper before reopening, rather than bypassing or deleting unknown locks. The first probe also corrected its expected HTTP admission status to the existing 202 contract.

The actual process regression discards the ACK response body after admission, stops the host, reopens with a rotated API token and recovers the exact original native job and receipt. It rejects the old transport token, altered payload, wrong host, principal, source version, policy credential and a concurrent launcher without changing persisted launch config/token. Revoked policy after reopen blocks receipt reads and dispatch before a model run. A second job is observed running while waiting for policy, then the process is forcibly killed; resume marks the existing attempt interrupted, pauses the agent with reconciliation required and does not create another job or replay an effect. These are actual Node processes, Python policy requests and native runtime records; no paid model calls. The paused coordinator in these fixtures is solely an inbox/recovery test harness, not a production persistent-organization execution design.

Evidence applies only to the frozen source and environment. The ready field is additive under `pida.local-host/1`; strict parent adapters must explicitly accept it. Existing old example workspaces have no manifest and are intentionally not automatically migrated. Source/config/provider/credential/Node upgrades require an explicit future migration. The synthetic Persona example does not persist canonical memory. Full service/app restart, Linux behavior and packaged desktop acceptance are separate gates.

Withdraw acceptance if rejected launches mutate config/token/runtime, another live process can open the same host, changed identity/profile silently opens, interrupted effects replay, repeated delivery creates a different native job, or current revoked policy authorizes work after reopen.
