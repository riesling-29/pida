# 파일을 지정하고 같은 작업 이어 보기 · 0.8.16

Studio와 단일 세션 TUI(`--main`)에서 파일·행 범위를 요청에 고정하고 같은 서버 기록을 열 수 있다. 멀티 에이전트 탭의 대상 고정 UI, DOM 요소 선택, 미전송 초안의 화면 간 동기화는 이 버전의 범위 밖이다.

## Web

1. 개발자·운영자 화면에서 파일을 연다.
2. 필요하면 시작행·끝행을 지정하고 **요청 대상으로 고정**을 누른다. 다른 파일을 열어도 고정 대상은 유지된다.
3. 요청을 보낸다. 파일이 그 사이 바뀌었으면 실행하지 않고 초안을 유지한다. 파일을 다시 읽고 새 버전으로 고정한다.
4. **서버의 공통 작업 기록**에서 접수 대상, 실제 변경, 검사 상태를 확인한다.
5. **같은 작업을 다른 화면에서 열기**에 표시된 세션 ID로 TUI를 열거나, 다른 세션 ID를 넣어 조회한다. 조회는 실행을 재시작하지 않는다.

## TUI

```powershell
npm run tui -- .\my-agent --main --session <세션-ID>
```

- F5 또는 `/read 경로`: 파일 열람. 줄 번호 표시.
- `/bind`: 읽은 파일 전체를 고정. `/bind 10 20`: 읽은 버전의 10~20행을 고정.
- `/unbind`: 고정 해제. 고정 대상은 입력란 위 상태에 계속 표시된다.
- `/review`: 최근 서버 기록. `/review 실행-ID`: 지정 기록.
- `/requests`: 접수 ID·실행 ID·상태 조회. 응답 유실을 새 실행으로 처리하지 않는다.
- `/web`: 같은 세션의 Studio 열기.

## 기록의 의미

파일 해시는 원래 UTF-8 바이트에서 계산한다. 경로·권한·행 범위·해시를 기존 실행 admission 안에서 검증하고 접수 기록을 저장한 뒤 Pi를 실행한다. 동일 세션·request ID·내용은 기존 결과를 재사용하며 내용이 바뀌면 충돌이다. 접수 후 종료 기록이 없는 요청은 자동 재실행하지 않는다.

작업공간 변경은 서버가 접수·종료 경계에서 잡은 Git checkpoint 사이의 관찰이다. 외부 편집까지 포함할 수 있으므로 에이전트 단독의 변경이라고 단정하지 않는다. 프로젝트 파일은 선택 파일의 전후 내용·해시를 표시하고, 기존 F6 전체 Git 변경과 구분한다. 일반 프로젝트 전체의 자동 snapshot/rollback은 제공하지 않는다.

검사 후 파일이 바뀌면 이전 버전의 검사로 표시하며 읽기 실패는 확인 불가다. 기존 manifest의 agent-supplied 검사와 독립 과제 수용 판정은 별개다. 대상 고정은 작업 맥락이며 새 쓰기 권한이나 OS sandbox가 아니다.

## 검증

실제 Pi·HTTP·파일·재시작 시험에서 stale 요청의 모델 호출 0회, CRLF 원본 바이트 해시, 잘못된 범위·경로 거절, 중복 접수, 기존 결과 재조회, 권한 경계, TUI 초안 복원과 양방향 기록 조회를 확인했다. Web 실제 이벤트 핸들러의 A 고정/B 열람·범위·거절 후 초안 유지도 통과했다.

로컬 실제 Chromium 실행은 OS의 `socket() EPERM`으로 차단됐다. `scripts/work-surface-browser-check.mjs`와 별도 CI job을 추가했으며, 브라우저 320/768/1440px·실제 클릭 통과는 그 실행 결과를 확인해야 한다. Linux TUI renderer의 입력·폭 회귀는 자동시험 범위이며 Windows IME와 실모델은 미실행이다.
