# Pida: 범용 core와 실사용 기본 하네스

기준일: 2026-11-02 KST. 상태: **사용자 요구사항과 개발 완료 기준**. 이 문서는 기능 구현 완료 보고가 아니다. 확인한 구현 기준은 개발 브랜치 `af86242365d6745d3737373042647ea46766ccc7`, Pida 0.7.0이다.

## 두 가지 제품 목표

1. **pida-core:** 업무 에이전트, 코딩 에이전트, 개인 비서, 웹 서비스 내장 에이전트 등 여러 형태에 기본 적용할 수 있는 실행 코어.
2. **Pida 기본 하네스:** 사용자가 집에서 Codex와 OpenClaw를 대신해 코딩과 개인 비서 업무에 실제로 사용할 수 있는 완성된 구성.

필요한 도구를 그때그때 추가할 수 있어야 한다. 확장성이 있다는 이유로 기본 코딩·개인 비서 기능을 빈 화면이나 예제로 남겨두지 않는다. 같은 core를 라이브러리로 쓰거나 기본 하네스로 실행할 수 있어야 한다. 이는 두 개의 별도 실행 엔진을 개발하라는 요구가 아니다.

이 문서는 이전 MAGI 패치의 선택적 도입 목록과 최소 연동 전략을 전체 제품 범위로 간주하지 않도록 보완한다. 기존 문서에서 미뤘던 기능도 아래 기본 기능에 해당하면 미완료 항목으로 계속 추적한다. 조직 단위 Schumpeter 및 Memory Substrate 개발은 여전히 이 작업의 범위 밖이다.

## 책임 경계

| 구성 | 소유하는 책임 | 실제로 제공해야 할 접점 |
| --- | --- | --- |
| 공통 core | 세션·컨텍스트, 실행 소유권과 상태, 도구 호출·인가, 취소·예산·오류 회복, 사건·결과·증거 계약 | UI 없는 SDK 사용, 동일한 상태를 전달하는 API/클라이언트 계약 |
| 실행 백엔드 | 모델 판단·도구 루프, 백엔드가 소유하는 세션과 네이티브 기능 | Pi SDK 또는 채택한 하네스의 공식 인터페이스. 한 실행에는 한 실행 소유자 |
| 기본 하네스 | 사용자 설정, 코딩 작업면, 개인 비서 진입점, 단일 사용자 상주 운영, 예약·채널·확장 관리 | 바로 시작할 수 있는 기본 구성과 실제로 작동하는 화면 |
| 확장 | 모델/인증 연결, 파일·셸·브라우저·검색·업무 도구, MCP, 채널, 스케줄러, 기억 제공자 | 문서화된 등록·설정·수명·권한·결과 계약 |
| 외부 시스템 | 조직 단위 임무 운영·PI 분석·장기 정체성/기억 등 | 관측·결과 내보내기 및 선택적 연결. 기본 개인 사용의 필수 의존성이 아님 |

위 구분은 논리적 책임이다. 패키지 여러 개로 즉시 분리하거나 모든 API를 다시 만드는 결정이 아니다. core를 가져다 쓰는 앱에 Web Studio, 코딩 도구, 브라우저, 특정 메신저, 외부 기억 서비스를 강제로 요구하지 않는다. 현재 Node 기반 구현을 모든 OS·모바일·브라우저 안에서 바로 실행할 수 있다는 주장으로 확대하지 않는다.

## core의 필수 계약

- 웹, CLI/TUI, 메신저, HTTP, 예약·이벤트 입력이 같은 실행 상태와 제어 계약을 사용한다. 채널마다 별도 에이전트 루프를 만들지 않는다.
- 시작·진행·입력/승인 대기·종료·실패·취소·한도·중단을 구별한다. 실제 실행 및 도구 호출 ID로 추가 지시, 취소, 승인 응답을 연결한다.
- 세션 저장·복원·압축, 가능한 백엔드의 steering/follow-up/분기를 실제 API와 클라이언트로 연결한다. 대화 분기와 파일 복원을 별개로 다룬다.
- 모델·실행기·도구의 지원 기능을 명시한다. 추론, 이미지, 도구 형식, 스트리밍, 재개·격리 등 미지원 기능을 조용히 지원하는 척하지 않는다.
- 일시적 네트워크 오류, 출력 한도, 도구 오류, 시간 초과, 취소와 상태 불명을 구별한다. 재시도는 횟수·총시간 한도와 실제 부작용 상태를 반영한다.
- 도구 권한은 실행 경계에서 강제한다. 정책이 이미 허용한 일상 작업마다 사용자 승인을 반복 요구하지 않는다. 새 범위의 권한과 필요한 외부 변경은 정책에 따라 처리한다.
- 사용자에게 보여주는 명령·결과와 기본 외부 관측 로그를 구분한다. 원문 입력·비밀값을 관측 로그에 무조건 복사하지 않는다.
- 실행 완료 선언, 실제 테스트 결과, 독립 검증을 구별한다. 미확인 결과는 UNKNOWN으로 남긴다.

개인 비서의 첫 채널은 현재 Web UI로 시작할 수 있다. 실제로 사용할 외부 채널 하나를 연결해도 모든 메신저를 지원했다고 주장하지 않는다. 코딩과 개인 비서는 같은 설치에서 사용할 기본 구성이다. 새로 만든 인격이나 별도 복제 런타임이 필수인 구조로 만들지 않는다.

화면은 현재 작업·변경·실행 결과·제어를 드러내는 간결한 구조를 유지한다. TempleOS에서 참고한 것은 직접성과 구조 노출이며 외형 복제가 아니다. TUI가 필요하면 기존 구현을 재사용한다. Web UI에서 기본 코딩 기능이 비어 있는 문제를 TUI 검토로 대신하지 않는다.

## 도구를 그때그때 붙이는 방식

도구 함수뿐 아니라 공급자 연결과 채널·기억 등 서비스 확장도 수용하되, 최소한 다음 정보와 수명을 명시한다. 아래는 요구사항이며 확정된 새 API 필드명이 아니다.

- 식별자·버전·출처·호환 core/백엔드 범위, 제공 기능, 설정 스키마.
- 요구 권한, 읽기/변경 등 부작용, 자격증명 참조, 취소·timeout 처리와 결과/오류 형식.
- 설치, 설정, 활성화, 실행 권한 부여, 업데이트, 비활성화, 제거를 구별.
- 사용자가 허용한 도구 집합에서 에이전트가 필요한 도구를 선택·발견할 수 있어야 함. 모델이 임의 설치로 자신의 권한을 확대하는 구조는 아님.
- 실행 중 도구를 바꿀 때는 진행 중 호출의 버전·정의를 고정하고, 변경 적용 시점을 표시. 즉시 hot reload를 보장하지 못하면 다음 요청/재시작 적용을 명시.
- 도구 등록부터 실제 호출·진행 표시·취소·오류·결과까지 통합. 등록 파일이 있다는 것만으로 도입 완료로 계산하지 않음.
- 확장 오류를 사용자에게 표시하고, 가능한 범위에서 해당 확장을 비활성화하여 복구. 같은 프로세스에서 실행되는 신뢰 코드가 OS 수준으로 격리된다고 주장하지 않음.

회사별 인증·토큰 처리·요청 절차는 비공개 연결 모듈로 둘 수 있어야 한다. 공개/공통 core에는 일반 연결 계약과 합성 fixture만 필요하다. 추가 헤더를 지원한다는 이유로 회사 API 호환 완료로 판정하지 않는다. 회사 모듈의 내부 규약이나 자격증명을 요구하거나 저장소에 수집하지 않는다. 집/회사 구성은 자격증명·도구·저장 경계를 분리한다.

## 재사용과 유지보수

사용자는 설계 참고에 그치지 않고 **원천 코드의 직접 복사·이식, 포크와 패키지/바이너리 재사용**을 적극 활용하라고 명시했다. 독립된 구현은 코드로 가져오고, 의존성이 큰 실행 구성요소는 가능한 한 통째로 연결한다. 언어가 다르다는 이유로 기능을 생략하지 않으며, 원천 구현을 TypeScript로 다시 작성하는 것을 기본 선택으로 삼지 않는다. Pida 고유의 코드가 필요한 부분은 사용자 작업면, 설정과 실제 연결 경계다.

검토한 MAGI/Codex 기준 커밋의 루트 라이선스는 Apache-2.0이다. 실제 가져오는 파일과 포함된 제3자 코드의 조건을 확인하고 LICENSE·저작권·해당 NOTICE를 보존하며 수정 사항을 표시한다. 가져온 코드의 원천 경로·커밋과 Pida 수정분을 기록한다. 원천 출처를 숨기거나 검사 부재를 재사용 근거로 삼을 필요가 없다. 이는 추후 코드 도입 원칙이며 이 문서 수정으로 원천 코드가 이식된 것은 아니다.

Pi의 이미 있는 기능을 빈 loader와 미노출 API로 남겨두지 말고 코딩 구성에 연결한다. MAGI·Codex에서 확인한 기본 기능을 적용 여부와 검증까지 추적한다. SDK·확장·독립 실행 구성요소·전체 하네스 연동 중 유지 비용이 적고 실제 요구를 충족하는 단위를 선택한다.

Codex exec-server 재사용과 전체 Codex app-server 연동은 검토 후보이며 현재 구현이 아니다. 모델 연결 프로토콜, 실제 격리, 승인, 프로세스 수명, UI 연결까지 확인해야 한다. 회사용 custom provider의 존재가 일반 코딩 기능을 생략하는 이유가 되어서는 안 된다.

원천 버전 고정 → 후보 업데이트 → 계약·대표 작업 검증 → 채택/되돌리기 흐름을 제공한다. 포크는 원천 변경을 추적하는 수단이며 자동 호환 보장은 아니다. 세션 형식 변경의 복구와 코드 rollback은 별도로 다룬다. 사용자에게 매번 내부 구현 선택과 병합 문제를 맡기지 않는다.

| 6 | 개인 비서 채널·예약·알림·기억 제공자 | 실제 채널 요청 → 조회/작업 → 알림; 예약 취소·재시작 복원·부작용 중복 방지 |
| 7 | 운영·업데이트·교체와 통합 실사용 | 설치·재접속·중단 복구·후보 업데이트 rollback, 집에서 쓰는 대표 작업 통과 |

연결 경계를 위한 작은 추가는 먼저 할 수 있으나, 기존 주요 API를 승인 없이 전면 교체하지 않는다. 단계별 구현 보고에서 전체 하네스 완성과 부분 구현을 구분한다. 실사용 검증은 실제 모델·파일·명령·브라우저·채널로 수행하며 mock/protocol fixture와 별도 기록한다.

**대체 가능 판정:** 코딩은 실제 저장소에서 다중 파일 작업·테스트·중간 지시·diff·재접속을, 개인 비서는 실제 사용하는 채널에서 반복 업무·예약·알림·연속성을 수행해야 한다. 성공 여부, 사용자 개입, 시간·관측 가능한 사용량, 남은 제약을 기록한다. 의존성 설치나 기능명만으로 Codex/OpenClaw 대체 완료라고 보고하지 않는다.
