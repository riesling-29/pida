# 상주 에이전트와 세 단계 기억 — 0.8

상주 에이전트는 이름·역할·기억·Pi 세션·작업 큐가 유지되는 실행 단위입니다. 대기 중에 모델을 계속 호출하지 않습니다. 브라우저를 닫아도 **Pida 서버가 실행 중이면** 작업은 진행됩니다. 운영체제 서비스 설치, 예약 작업, 메신저 수신은 이 버전에 포함되지 않습니다.

## 시작

기존 워크스페이스를 그대로 사용합니다. 서버를 종료한 뒤 코드를 갱신하고 빌드합니다.

```powershell
git pull --ff-only origin fix/runtime-stabilization-00-02
npm ci --ignore-scripts
npm run build
npm start -- .\my-agent --open
```

다른 브랜치에 있다면 먼저 변경 파일을 확인하고 해당 브랜치로 전환해야 합니다. 위 명령은 기존 작업 파일을 삭제하거나 초기화하지 않습니다. 설정 위치는 계속 `my-agent/pida.config.json`입니다.

화면의 **상주 에이전트** 탭에서 이름·역할·페르소나를 입력해 등록합니다. 예를 들어 `개발`, `검토`, `생활 도우미`를 각각 등록하고 작업을 제출할 수 있습니다. 일반 데모 모델은 임의의 코딩이나 기억 도구 선택을 하지 않습니다. 실제 코딩은 모델 설정에서 연결한 모델을 사용합니다.

- 각 에이전트의 작업 목록, 현재 도구, 마지막 신호, 부분 응답, 최종 결과를 확인합니다.
- **일시정지**는 다음 작업 시작을 막습니다. 현재 작업은 해당 작업의 **중단**으로 취소합니다.
- 실행 중 추가 지시는 현재 run ID를 확인하고 Pi steering에 전달합니다. 이 추가 지시 큐는 프로세스 장애를 견디는 큐가 아닙니다. 재시작 후에도 반드시 남아야 할 요청은 새 작업으로 제출합니다.
- 각 에이전트의 작업 파일은 별도 저장됩니다. 개발자 탭의 서비스 화면과 자동으로 같은 화면이 되지 않습니다. 상주 탭의 작업 파일 조회에서 실제 산출물을 읽을 수 있습니다.
- `project`를 켜면 기존 프로젝트 파일·셸 도구도 사용할 수 있습니다. 같은 프로젝트의 메인 화면과 에이전트 실행은 공유 실행 잠금으로 직렬화합니다. 프로젝트가 없으면 에이전트별 작업공간에서 설정된 동시 실행 수만큼 실행합니다.

선택 설정:

```json
{
  "agents": { "enabled": true, "maxConcurrent": 3 },
  "skills": ["skills/review/SKILL.md"]
}
```

기존 전체 설정에 위 필드를 추가합니다. `agents` 생략 시 활성화·최대 3개 동시 실행입니다. 등록 한도는 기본 32명, 작업 이력 한도는 2,000건이며 한도 도달 시 오류를 반환합니다. 에이전트는 모델의 도구 호출로 `agent_list`, `agent_delegate`, `agent_job_status`를 사용할 수 있습니다. 위임은 비동기이며 최대 깊이 2, 자기 자신·조상으로의 순환은 거절합니다. 타 에이전트의 기억을 자동 공유하지 않습니다.

## 기억의 의미

| 층 | 내용 | 변경 방식 |
| --- | --- | --- |
| 페르소나 | 정체성, 역할의 연속성, 기본 원칙 | 소유자가 수정, 이전 버전과 출처 보존 |
| 장기 기억 | 사실 주장, 결정, 경험, 교정 | 출처·작성 주체 기록, 대체·철회 명시 |
| 단기 정보 상태 | 목표, 현재 이해, 불확실성, 관계, 다음 행동 | 이전 상태를 부모로 연결, 현재 head와 일치할 때만 전이 |

‘영구’는 페르소나 유지 목적이며 불변이라는 뜻이 아닙니다. ‘단기’도 디스크에 저장되어 재시작 뒤 이어집니다. `queued/running/completed` 같은 작업 상태와 정보 상태는 별개입니다. 작업이 끝났다는 이유만으로 새 이해나 관계를 자동 생성하지 않습니다.

소유자는 화면에서 세 층을 조회하고 페르소나·경험·현재 정보 상태를 수정할 수 있습니다. 모델은 허용된 기억 도구로 경험과 정보 상태를 갱신하며, 페르소나 수정 도구는 없습니다. 모델의 경험 기록은 `agent-report`이고, 독립 검증된 사실로 취급하지 않습니다. 소유자의 기록을 모델이 자동 대체할 수도 없습니다.

출처는 `message:...`, `run:...`, `artifact:...`, `owner:manual`처럼 식별자를 사용합니다. 출처 문자열의 존재는 해당 증거의 진실성을 증명하지 않습니다. 일반 로그와 별도로 기억 내용은 비공개 상태 저장소에 남습니다. 프롬프트·키·비밀번호를 기억으로 저장하지 마십시오.

SDK의 `transitionAgentMemory`는 `branch: true`로 활성 head를 움직이지 않는 분기를 만들 수 있습니다. 병합은 현재 head를 포함한 여러 `parentIds`와, 서로 다른 각 정보 필드의 해결/미해결 목록을 요구합니다. 화면은 기본 선형 전이를 제공하며 복잡한 분기·병합은 SDK로 수행합니다. 기억 전체를 매번 전송하지 않고 페르소나·현재 상태·최근 활성 경험의 제한된 참조 문맥을 전달하며, 상세 기록은 기억 도구로 조회합니다.

## 중단과 복구

프로세스가 강제 종료되면 실행 중 작업은 재시작 시 `interrupted`로 기록하고 에이전트를 일시정지합니다. 이전 요청을 자동 재실행하지 않습니다. 같은 프로젝트를 사용하는 다른 에이전트도 해당 복구가 끝날 때까지 쓰기 실행을 시작하지 않습니다.

잠금 오류가 있으면 이전 프로세스가 실제로 종료됐는지 확인한 뒤:

```powershell
node dist/cli.js unlock .\my-agent
npm start -- .\my-agent --open
```

`unlock`은 같은 호스트에서 종료가 확인된 프로세스의 루트·에이전트 런타임 잠금만 해제합니다. 다른 호스트·살아 있는 프로세스·소유자를 알 수 없는 잠금은 제거하지 않습니다. 세션이나 산출물은 삭제하지 않습니다.

메인 개발자/일반 세션의 미확인 변경도 공유 프로젝트 에이전트 실행을 차단합니다. 메인 세션은 `pida recovery SESSION_ID .\my-agent`로 영수증을 조회하고 실제 상태를 확인한 뒤 `pida recovery resolve SESSION_ID EFFECT_ID applied .\my-agent` 또는 `not_applied`로 기록합니다. Pida 서버가 실행 중이어야 합니다. 이 명령도 원래 작업을 재실행하지 않습니다.

상주 탭에서 **미확인 변경 확인**을 열고 실제 파일·외부 상태를 조사합니다. 각 미확인 도구 변경을 적용됨/미적용으로 기록하고 검사 확인을 제출한 뒤 별도로 **재개**합니다. 이 조작은 과거 작업을 성공으로 바꾸거나 다시 실행하지 않습니다. 필요하면 새 요청 ID로 후속 작업을 제출합니다. 메모리 쓰기 중 강제 종료로 남은 `memory.lock`은 자동 해제하지 않으며, 저장 파일 보존 후 별도 운영 복구가 필요합니다.

## 현재 경계

- 전역 모델 설정 변경은 에이전트 실행이 끝난 뒤 적용합니다. 다음 에이전트 작업부터 저장된 세션을 유지하면서 새 모델/인증 설정으로 런타임을 다시 엽니다. 에이전트별 모델·도구·프로젝트 프리셋의 화면 선택은 후속 작업입니다. 임베딩 호스트는 `createRuntime(profile)`에서 이를 직접 지정할 수 있습니다.
- 명시적 `skills`와 프로젝트 루트 `AGENTS.md`를 연결합니다. 부모 폴더·전역 패키지의 지시/확장은 자동 발견하지 않습니다.
- 프로젝트 변경 보기는 실제 Git staged/working-tree diff와 untracked 이름을 보여줍니다. 읽기 전용·크기 제한이 있는 현황이며 원자적 체크포인트, 프로젝트 파일 복원, 독립 검증 근거가 아닙니다.
- 사내 전용 인증/프로토콜은 [호스트 커넥터](PRIVATE-CONNECTORS.md)로 연결합니다. 서버 URL과 추가 헤더만으로 모든 게이트웨이를 지원한다고 가정하지 않습니다.
- 호스트 셸은 호스트 권한으로 실행합니다. OS 샌드박스, PTY, 메신저·예약 채널, Codex/OpenClaw 전체 기능 동등성은 제공하지 않습니다.

## 임베딩

`AgentSupervisor`, `AgentMemoryStore`, `memoryTools`, `createAgentTools`, `loadProviderConnector`는 UI 없이 사용할 수 있습니다. `createPidaServer`에는 선택적으로 `agents`, `agentMemory`, `agentWorkbench`, `projectView`를 연결합니다. 에이전트 관리 API는 `pida:agents`, 기억은 `agent:memory:read/write`, 복구는 `pida:recover` 권한을 확인하고 소유자를 다시 검사합니다. 등록 요청으로 경로·도구 권한·자격증명을 지정할 수 없습니다.

워크스페이스 호스트는 종료 시 `await app.close()`를 호출합니다. 기존 `await app.runtime.close()`도 전체 워크스페이스 자원 해제를 유지합니다. 브라우저의 `PidaClient`는 Node 구현을 번들링하지 않는 타입 전용 의존성과 HTTP를 사용합니다.
